Session 9 — Oct 10, 2026: Unity Core to Vibeforge Design Push

Took the app from a non-functional WIP snapshot to a Joe-verified end-to-end loop: import from Unity Core, generate, approve, export at exact pixel size, upload via CRM, and receive portal feedback back in Unity Core.

  • Real IPC restored: Handlers put back and the AI, asset, and settings channels wired through, replacing the partially stubbed snapshot so the app actually runs end to end.
  • Exact-pixel PNG export: Approval gate requires the asset to be approved ON DISK; renders at scale 1; verifies exact width × height before writing; never overwrites (numeric suffix); records every render in exports/export-manifest.json.
  • Import surface: Unity Core import types, an extended creative brief, and custom format specs identified as custom-<platform>-<formatName>.
  • Unity Core importer: unity:import-manifest drives "Import from Unity Core..." on the Dashboard. It reads manifest.json (1.0 and 1.1), creates one project per unity.adIntakeId, fills empty brand fields, adds new formats and assets, and never overwrites designs, approvals, or edits. Video formats are reported as skipped; contact data is never read or copied.
  • Campaign export folder: Renders land in <campaignFolder>\exports whenever a unity block exists.
  • Electron-only puppeteer fix: puppeteer is ESM-only and Electron 33's Node 20 cannot require() it, so render-service now loads it through a runtime import(). The proof has to be run inside Electron (npx electron), not plain Node.
  • Joe's end-to-end verification: import → AI generation → approve → export at exact size → upload via CRM → client portal shows the PNG → portal feedback arrives in Unity Core.
  • Open follow-ups: custom formats display as "custom <Platform> <Format>"; very wide banners (970x90, 970x250) lay out badly; video formats can export as still PNGs; job approval is all-or-nothing; intake-service.ts still has fake default colors/ids.
